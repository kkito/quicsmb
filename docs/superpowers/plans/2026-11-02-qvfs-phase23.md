# qvfs Phase 2/3 Implementation Plan（传输+卷+双daemon+FUSE+面板+e2e）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 打通 VPS↔家里完整回路：xfer 编解码、volume 读写、disk 落盘、qvps/qhome 双 daemon、FUSE 挂载、面板扩展、e2e 回环。

**Architecture:** volume 为核心（cache+metastore+chunk 组装，fetch 回调注入）；xfer 只做帧编解码跑在 QUIC stream 上；disk 是家里文件区间读写；daemon 只做胶水。

**Tech Stack:** Go 1.25，quic-go v0.59.0（复用 internal/quic），go-fuse/v2 v2.12.1，标准库 web。

## Global Constraints

- 模块名 `quicsmb` 不变，所有 import 为 `quicsmb/internal/...`。
- go 命令必须带 `GOFLAGS=-mod=mod GOPROXY="file:///Users/kkito/go/pkg/mod/cache/download" GOSUMDB=off`；go-fuse 已进 go.mod（v2.12.1），从本地 cache 安装无需网络；如缺包可用 `GOPROXY=https://goproxy.cn` 补一次。
- 单测零网络零 root；FUSE 本体不进单测，靠 e2e。
- 现有 web 面板不破坏：扩展用可选接口断言，存量测试必须全绿。
